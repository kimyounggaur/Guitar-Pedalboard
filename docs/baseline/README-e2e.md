# 브라우저 시나리오(E2E) 기준선

실제 Chrome 에서 앱을 열어 화면 배치·도달성·시작 동작을 재는 시험이다(설계서 6.3절). 오디오 렌더 프로브(`README.md`)가 '소리'를 재듯, 이쪽은 '화면에서 손이 닿는지'를 잰다.

| 파일 | 내용 |
|---|---|
| `e2e.json` | E-04(S1.6 부터)와 E-06(S1.8 부터) 시험이 남긴 기준 측정값. 두 시험 모두 정식 단언이고, 화면 프로필 × 조건별로 한 덩어리 |
| `screenshots/` | 지금 상태를 눈으로 보기 위한 대표 스크린샷 6장(휴대폰 390×844 도크 접힘·펼침, 노트북 1280×800·1440×900 패널 펼침, 1024×768 서랍 열림, 1280×800 기타 연결 뒤). 비교에는 쓰지 않는다 |

## 쓰는 법

```bash
npm run build                         # 시험은 빌드 결과(dist/)를 vite preview 로 서비스한다
npm run e2e                           # 빌드까지 알아서 한다. 전체 109개, 약 4분
E2E_SKIP_BUILD=1 npm run e2e          # dist/ 가 이미 있을 때(CI 는 앞 단계에서 빌드해 이렇게 돌린다)
npm run e2e -- --grep "E-23"          # 일부만
E2E_UPDATE_BASELINE=1 npm run e2e     # 기준선(e2e.json)과 대표 스크린샷 갱신 (의도한 변화일 때만)
# 측정값을 남기는 시험만 돌려 갱신할 수도 있다(E-04 + E-06, 약 1분. 병합이라 나머지 값은 그대로다)
E2E_UPDATE_BASELINE=1 E2E_SKIP_BUILD=1 npx playwright test e2e/tests/e04-phone-reachability.spec.ts e2e/tests/e06-desktop-layout.spec.ts
```

| 환경 변수 | 뜻 |
|---|---|
| `E2E_SKIP_BUILD=1` | `npm run build` 를 건너뛰고 있는 `dist/` 를 쓴다 |
| `E2E_UPDATE_BASELINE=1` | E-04·E-06 이 잰 값을 `docs/baseline/e2e.json` 에 병합하고 대표 스크린샷을 `screenshots/` 로 복사한다(조건별로 값 전체를 교체한다) |
| `E2E_CHROME_PATH` | 시험에 쓸 Chrome 실행 파일. 없으면 Playwright 가 받은 Chromium(`npx playwright install chromium`)을 쓴다. `CHROME_PATH`(반응형 시험·프로브가 쓰는 변수)와는 일부러 분리했다 |

- 기준선을 갱신하는 커밋의 메시지는 `baseline: {Step ID} {이유}` 로 쓴다. 이유 없이 갱신하지 않는다.
- 시험 결과(`test-results/`)와 보고서(`playwright-report/`)는 git 에 넣지 않는다. CI 에서 실패하면 두 폴더를 `e2e-report` 이름으로 올린다(7일 보관).
- 가짜 마이크용 WAV 는 `node scripts/make-fixture-wavs.mjs` 가 `e2e/fixtures/*.wav` 로 만든다(git 제외). `e2e/global-setup.ts` 가 없으면 만든다.

## 하네스 구성

- 설정: `playwright.config.ts` — 작업자 1개, 데스크톱 Chrome 프로필, 마이크 권한 허용, `vite preview` 를 웹 서버로 띄움(`http://127.0.0.1:4173/Guitar-Pedalboard/`).
- 가짜 마이크: Chrome 인자 `--use-fake-ui-for-media-stream`, `--use-fake-device-for-media-stream`, `--use-file-for-fake-audio-capture=<WAV>`. WAV 는 브라우저를 띄울 때만 정할 수 있어서 `launchWithMic(wav)` 픽스처가 WAV 마다 브라우저를 새로 띄운다.
- 도우미(`e2e/helpers/`):
  - `geometry.ts` — 도달성(`reachable`: 뷰포트 가운데로 스크롤해 가운데 히트 테스트, `reachableAboveDock`: 휴대폰 도크 위 빈 영역 기준), 노출 비율, 글자 겹침, 도크 위에 온전히 보이는 노브 수(`visibleKnobs`).
  - `switches.ts` — 스위치 15개 측정(`measureSwitches`: 데스크톱, `measureSwitchesAboveDock`: 휴대폰 도크 기준).
  - `app.ts` — 앱 조작(`connectGuitar`, 도크 탭 고르기 `selectMobileTab`, 도크 펼침·접힘 `setMobileDock`: `--dock-h` 가 실제 높이를 따라올 때까지 기다림).
  - `touch.ts` — CDP `Input.dispatchTouchEvent` 로 손가락 드래그를 보내고 스크롤이 가라앉기를 기다린다(Playwright 의 `touchscreen` 은 탭뿐이다).
  - `mocks.ts` — 저장소 차단·가득 참, Web MIDI, 문서 숨김 흉내, `getUserMedia` 오류 7종, `AudioContext` 추적, 출력 가드 관찰.
  - `teardown.ts`(정지 정리 관찰, E-01), `screens.ts`(화면 프로필 11종), `fixtures.ts`·`env.ts`(브라우저 띄우기·환경 상수), `record.ts`(측정값 기록).
- 도우미 자체의 시험은 `e00-harness.spec.ts`(11개). 가려진 요소를 정말 '도달 불가'로 가려내는지(도크 가장자리 요소 포함), 겹친 글자를 세는지, 모의가 이름 그대로 동작하는지를 확인한다.
- 저장소·오류 시험은 `e05-storage.spec.ts`(E-05, 7개, S1.7) — 아래 'E-05' 절.
- 결함 회귀 시험은 `f-regressions.spec.ts`(11개) — F-1(숫자 입력 겹침)·F-3(세로 터치 스크롤)·F-4(노브 가운데 드래그)가 되살아나면 실패한다. 고치기 전 CSS 로 되돌려 돌리면 실패함을 확인했다.
- 데스크톱 배치 시험은 `e06-desktop-layout.spec.ts`(E-06, 31개, S1.8) — 아래 'E-04 와 E-06' 절.
- 타입: `tsconfig.e2e.json` 이 `e2e/` 와 `playwright.config.ts` 를 검사한다(`npx tsc -p tsconfig.e2e.json --noEmit`). `@types/node` 는 앱의 `setTimeout` 반환형을 바꿔 `AutoWahEffect.ts` 를 깨뜨려서 넣지 않고, 쓰는 Node API 만 `e2e/types/node-shim.d.ts` 에 직접 선언했다.

## E-04 와 E-06 (둘 다 정식 단언)

- **E-04 휴대폰 도달성**은 S1.6 에서 정식 단언이 되었다. 세 화면(390×844, 360×640, 412×915) × 도크 접힘·펼침(입력·미터·프리셋 탭)에서 스위치 15개 모두 도달, 상자 ≥ 44×44, 390×844 첫 화면에 노브 ≥ 2개, 끝까지 스크롤하면 마지막 페달이 도크 위에서 끝나는지를 `expect` 로 가른다. 측정값은 그대로 `e2e.json` 에도 남긴다. 같은 파일에서 순서 변경 알림 `.chain-toast` 가 도크 접힘·펼침(세 탭) 모두에서 도크 윗선 11~14 px 위에 놓이는지도 화면마다 하나씩 본다(S1.7, L-54 — 알림은 페달 순서를 바꿀 때만 떠서 같은 클래스의 요소를 붙여 CSS 규칙만 잰다).
- **E-06 데스크톱 배치**는 S1.8 에서 기록 모드에서 정식 단언이 되었다(`@record` 태그와 '기록 모드' 문구는 없앴다). 31개 시험이다.
  - **화면 폭 8개(768·1024·1280·1366·1440·1536·1680·1920 px) × 오른쪽 패널 펼침·접힘 16조건**: 카드 15개 안의 글자 상자 겹침 0, 가로 넘침 0, 페달 카드 폭 ≥ 300 px, 스위치 15개의 수. 패널이 보드 옆에 붙은 경우(1280 px 이상)와 서랍이 닫힌 경우는 스위치 15개 모두 도달·100% 보임까지 단언한다. **서랍을 연 상태(768·1024 px)는 서랍과 막이 보드를 덮는 것이 설계라 스위치 노출을 단언하지 않고**, 대신 열기 전과 보드 배치(칸 수·카드 폭·첫 카드 위치)가 같은지, 겹침 0·가로 넘침 0 인지를 본다(REFACTOR_LOG L-73). 기준선에는 그 상태의 스위치 도달이 0/15 로 남아 있는데 의도한 값이다.
  - **연결 뒤 8개**: 가짜 마이크로 연결하면 입력 줄이 한 줄 상태 막대로 줄어 연결 전보다 첫 카드 윗선이 올라오는지, 막대의 장치·채널·지연·트림·연결 해제·Panic·'입력 설정'이 보이는지, '입력 설정' 상세가 기본 접힘이고 토글로 펼쳐지는지, 가로 넘침 0. **1280×800 에서는 첫 페달 카드 윗선 ≤ 320 px**(설계서 수용 기준)를 단언한다. 첫 화면에 보이는 첫 줄 스위치 수·막대 높이·로고 높이는 기준선에 기록만 한다.
  - **서랍(768~1279 px)**: 처음엔 닫힘, 열어도 보드 배치 그대로, 닫기 버튼·Esc·바깥 막으로 닫힘, 포커스가 열 때 닫기 버튼으로 가고 닫으면 여는 버튼으로 돌아옴, 열림은 저장하지 않음(`guitar-pedalboard:ui` 에 안 씀), 새로고침하면 닫힘. 서랍 안 선택 상자에서 누른 Esc 는 서랍을 닫지 않는다.
  - **붙은 패널(1280 px 이상)**: 처음엔 열림, 접으면 `{"sidebarOpen":false}` 를 저장하고 새로고침해도 유지, 다시 펴면 true. 창 폭이 경계를 오가도 두 방식이 서로의 선택을 건드리지 않는다. **1279·1280 px 양쪽 정확한 폭에서 JS(`useSidebar` 의 `matchMedia`)가 고른 방식과 CSS 가 그린 방식(서랍은 `position: fixed`, 붙은 패널은 보드 오른쪽 옆)이 같은지** 본다 — 기준 폭이 두 곳(TS 상수·CSS)에 있어 어긋나기 쉽다. JS 기준을 1200 으로 바꿔 빌드하면 1279 px 시험이 실패함을 확인했다.
  - **좁은 카드(컨테이너 쿼리)**: 카드 안쪽 폭 ≤ 340 px 이면 Tremolo 의 Shape 가 선택 상자로, 넓으면 세 버튼으로 보이고 선택 상자로 바꾼 값이 같은 파라미터에 반영된다.
  - 값은 지금도 기준선 `e2e.json` 에 남긴다(`E2E_UPDATE_BASELINE=1` 일 때만 갱신).
  - **하지 않는 것**: 설계서의 '높이 900 px 에서 첫 줄 페달의 스위치가 스크롤 없이 보임'은 단언하지 않는다. 스위치가 카드 맨 아래에 있어 카드 속을 다시 짜야만 가능하다(L-71). 첫 화면 노출 수(연결 전·후 모두 0)만 기록한다.

## E-05 저장소·오류 (정식, S1.7)

`e2e/tests/e05-storage.spec.ts` 7개. 서비스 워커를 쓰지 않는다(`test.use({ serviceWorkers: 'block' })`) — 서비스 워커가 가운데서 요청을 받으면 `page.route` 가 닿지 않는다.

| 시험 | 확인하는 것 |
|---|---|
| 저장소 차단(SecurityError) | 흰 화면 없이 열림, 효과 스위치·노브·프리셋 불러오기 동작, 알림 `storage:blocked` 한 번(닫은 뒤 다시 써도 안 뜸), 처리되지 않은 예외 0 |
| 저장 공간 가득 참(QuotaExceededError) | 같은 확인, 알림 `storage:quota` |
| 깨진 저장값(픽스처 03) | 기본값으로 열림(켜진 페달 5개), 깨진 세 키가 원문 그대로 `…:corrupt-<시각>` 로 보관, 알림 `storage:corrupt` 한 번 |
| 렌더 예외 | 한국어 오류 화면과 포커스, AudioContext 모두 closed·마이크 트랙 모두 ended, 오류 정보 복사(클립보드 내용), 다시 시도, 다시 연결 |
| 저장된 설정 때문에 죽음 → 초기화 | 새로고침해도 오류 화면, 초기화는 두 번 묻고 취소하면 그대로, 초기화 뒤 `guitar-pedalboard:*` 는 없고 내 프리셋 키는 남음 |
| 앱 스크립트 실패 | 정적 안내가 뜨고 '페이지 다시 불러오기'로 복구 |
| 이벤트·타이머·약속 오류 | 알림 한 장(+ 오류 정보 복사), 중단된 요청·ResizeObserver 알림은 걸러짐, 앱은 그대로 |

- **렌더 예외를 일으키는 방법.** 앱에 시험용 문이 없다. 시험이 `Number.prototype.toFixed` 를 던지게 만들면 코러스 Rate 의 'n.n Hz' 같은 소수 표시가 그려질 때 렌더 예외가 난다. 연결해 둔 동안은 미터가 계속 다시 그려져 곧바로 죽는다. '저장된 설정 때문에 열 때마다 죽는' 상태는 init 스크립트가 실제 저장 키 `guitar-pedalboard:midi` 가 있을 때만 던지게 해서 흉내 낸다. 프리셋 가져오기로 숫자 자리에 문자열을 넣는 방법도 통하지만, S2.1 의 불러오기 검증이 막으면 깨지므로 쓰지 않았다(REFACTOR_LOG L-67). 소수 표시가 앱에서 모두 사라져 시험이 '예외가 나지 않아' 실패하면 `breakRendering` 의 대상 함수만 바꾼다.
- **클립보드.** 오류 정보 복사 시험은 `launchWithMic` 로 `clipboard-read`·`clipboard-write` 권한을 준 컨텍스트에서 돈다.
- **앱이 다시 쓰기 전의 저장소.** 초기화 시험은 init 스크립트가 새로 열릴 때마다 그 시작 직전의 `localStorage` 키 목록을 `sessionStorage` 에 남기게 해서, 앱이 기본값을 다시 쓰기 전의 상태를 본다.

### E-04 휴대폰 — 15개 페달 스위치 도달 (이전 기준선은 접힘 0/15, 펼침 0/15)

모든 값이 세 화면에서 같은 15/15 이고, 상자 크기는 최소 54×101 px 이다. 도크 위 빈 영역의 높이(`freeHeight`)와 끝까지 스크롤했을 때 마지막 페달과 도크 사이 여백은 다음과 같다.

| 화면 | 접힘: 빈 영역 | 접힘: 첫 화면 노브 | 펼침: 도크 높이(50dvh 이하) | 마지막 페달 아래 여백 |
|---|---|---|---|---|
| 360×640 | 582 px | 3개 | 320 px | 27.3 px |
| 390×844 | 786 px | 5개 | 422 px | 27.3 px |
| 412×915 | 857 px | 5개 | 458 px | 27.3 / 27.8 px |

접힘 상태의 도크 높이는 58 px 이다(빈 영역 = 화면 높이 − 58). 펼침은 입력·미터·프리셋 탭을 각각 확인했고 값이 같았다. 기준선 `e2e.json` 에는 `input` 탭의 값이 `tabs` 안에 들어 있다. 마지막 페달 아래 여백은 S1.6 때보다 0.5 px 늘었다(26.8 → 27.3, 27.3 → 27.8) — S1.8 이 카드 높이를 바꾸면서 생긴 반올림 차이이고 단언(≥ 허용치)은 그대로 통과한다.

## 고친 결함과 후보 (설계서에 없음)

**F-1 — 그래픽 EQ 숫자 입력이 투명한 전체 세로 막대가 되어 주 화면의 마우스·터치를 가로챘다. (S1.6 에서 고침, 커밋 `ce5b95f`)**

- 원인: `src/styles/pedals.css` 의 `.vertical-fader input { position: absolute; z-index: 3; inset: 0; … opacity: 0 }` 가 페이더의 슬라이더뿐 아니라 숫자 입력 `input.knob-number-input` 까지 잡았고, 바깥 `.vertical-fader` 에 `position` 이 없어 `inset: 0` 이 화면 전체 열을 기준으로 퍼졌다. 15개 페달 스위치가 전부 투명 입력 15개에 가려졌다(실제 `page.mouse.click` 도 가로채임, 키보드 Enter 는 동작).
- 들어온 시점: 설계서 기준 커밋 `4ac9cf7` 이후(커밋 `39bac60`, PR #1 병합). 배포된 앱에도 있을 가능성이 높다. **고침은 `phase/1` 브랜치에만 있고 배포하지 않았다.**
- 고침: 규칙을 `.vertical-fader-rail input` 으로 좁히고, 숫자 입력은 자기 칸 안(`.vertical-fader { position: relative }`)에만 머물며 `pointer-events: none` 으로 두었다. 키보드·스크린리더 포커스가 오면 드러나서(opacity 1) 쓸 수 있다. **터치 사용자는 그래픽 EQ 숫자 입력을 여전히 볼 수도 쓸 수도 없다**(접근성 후속 과제).
- 하네스: 한동안 `connectGuitar` 가 클릭 대신 포커스 + Enter 를 썼다. S1.6 에서 걷고 실제 `click()` 으로 돌아왔다.

**F-3 — 모바일 `.pedal-board { touch-action: pan-x }` 가 페달 카드 위에서 시작한 세로 터치 스크롤을 막았다. (S1.6 에서 고침, 커밋 `379a585`)**

- 390 px 폭에서 카드 높이가 약 1,100 px 이라 손가락이 거의 항상 카드 위에서 시작하는데, 세로로 끌어도 문서가 움직이지 않았다(0 px). `touch-action: manipulation` 으로 바꾸니 285 px 움직인다(가로 스와이프는 그대로). 아래쪽 스위치로 내려가는 길이 막혀 있던 별개의 원인이다. 배포된 앱에도 있을 가능성이 높다.

**F-4 — 노브의 장식 층이 투명한 range 입력의 가운데를 덮어, 노브 한가운데를 마우스로 끌어도 값이 안 바뀌었다. (S1.8 에서 고침, 커밋 `3b1b655`)**

- 원인: 노브 껍데기의 링·바늘·가운데 캡(Noise Gate 의 `i`, 공용·Compressor·Drive·Reverb 껍데기의 `::before`·`::after`)이 `pointer-events` 제한 없이 입력 위에 겹쳐 있어, 가운데를 누르면 입력 대신 장식이 포인터를 받았다. 1920×1080 에서 range 입력 101개 중 **13~14개**의 가운데가 그랬다(S1.8 직전 코드 `0f56ef7` 에서 회귀 시험이 14곳을 잡았고, 카드 배치를 바꾼 뒤의 스캔은 13곳이었다 — S1.6 의 추정은 착시가 아니었다). 고치기 전에는 그 노브의 가운데를 끌어도 값이 그대로였고, 가운데가 비어 있던 노브(대조군 10개)는 바뀌었다. 앱 기준 커밋 `2a5ab81` 에서도 같은 CSS 라 오래된 결함이고 배포된 앱에도 있을 가능성이 높다. **고침은 `phase/1` 브랜치에만 있고 배포하지 않았다.**
- 고침: `pedals.css` 끝에 장식 층 네 곳(`::before`·`::after`·`i`·`i::after`)에 `pointer-events: none`(대상: 클래스 이름에 `knob-shell` 이 든 껍데기 전부와 `.knob-control-shell`). 노브를 조작하는 **방식** 자체(S4.4 범위)는 바꾸지 않았다. 따로 떼어 cherry-pick 할 수 있다.
- 회귀 시험: `f-regressions.spec.ts` 5개(모든 노브 가운데의 히트 테스트 + 장식 층 종류별 마우스 끌기 4개). `0f56ef7`(고치기 전) 코드에서 돌리면 5개 모두 실패한다(히트 테스트가 14곳을 잡고, 끌기 4개는 값이 그대로).
- **터치로는 확인하지 못했다.** 손가락으로 가운데를 끌었을 때 같은지 사람이 본다.

## 아직 사람이 확인해야 하는 것

- 위 F-1·F-3 이 실제 배포 사이트(GitHub Pages)에서도 일어나는지, 그리고 고친 빌드에서 사라지는지 — 실제 휴대폰에서 페달 카드 위로 손가락을 끌어 스크롤해 보고, 접힘·펼침 도크에서 스위치 15개를 눌러 본다.
- iOS Safari 의 주소창 변화(`dvh`)와 노치 기기의 안전 영역에서 도크가 화면의 50% 를 넘지 않고, 마지막 페달이 도크에 가리지 않는지(안전 영역 높이가 페이지 아래 여백에 한 번 더 더해져 있어 노치 기기에서는 여백이 조금 넉넉하다).
- 첫 화면에서 노브가 어떻게 보이는지(390×844 에서 5개), 기본 탭이 '페달' 이라 처음 기타를 연결하려면 '입력' 탭을 한 번 눌러야 하는 흐름이 괜찮은지.
- 대표 스크린샷 6장이 실제 화면과 같은지(Chrome 헤드리스와 기기 브라우저는 글꼴·여백이 조금 다를 수 있다).
- E-04 는 기하학적 히트 테스트다(손가락 터치는 스크롤 시험에서만 CDP 로 흉내 냈다). 진짜 터치의 눌림 인식은 사람이 본다.
- E-06 의 '글자 겹침 0' 은 이 하네스의 정의(같은 카드 안에서 서로 다른 글자 상자가 가로·세로로 2 px 이상 겹침)에 따른 값이다. 1~2 px 닿는 것이나 글자와 그림(LED·풋스위치)이 눈으로 어색하게 붙는 것은 세지 않는다 — Compressor·EQ·Crunch·Fuzz 의 다시 짠 얼굴을 눈으로 본다. Figma 시안이 따로 있으면 대조한다(L-70).
- S1.8: 실제 노트북·태블릿 브라우저에서 오른쪽 패널 서랍(768~1279 px)의 열고 닫는 느낌(Esc·바깥 막 클릭·닫기 버튼), 창 크기를 끌어 1280 px 경계를 오갈 때, 실제 오디오 인터페이스를 연결한 상태 막대(두 줄로 접힌 1280~1680 px 와 한 줄인 1920 px), 카드가 340 px 를 오가며 갑자기 다른 배치로 바뀌는 모습, Tremolo 선택 상자, 키가 커진 카드(L-70·L-74), 노브 가운데를 실제 마우스·손가락으로 끌기(F-4).
